- Status: Accepted
- Date: 2026-10-12

## Context and problem statement

The project needs public docs that stay in step with the code: guides, decision records, a behaviour specification and an API reference. A docs build should fail when links or generated content break, and public exports should not ship undocumented.

## Considered options

- Markdown files in the repository only.
- A hand-written static site generator setup.
- Astro with Starlight, the API reference generated by TypeDoc, and lint rules that require TSDoc.

## Decision outcome

Astro with Starlight (`astro`, `@astrojs/starlight`, `@astrojs/check`) hosts the site in `apps/docs`. `starlight-typedoc` with `typedoc` and `typedoc-plugin-markdown` generates the API reference from TSDoc on `@fpving/plugin-sdk` and `@fpving/core`. `eslint-plugin-jsdoc` requires TSDoc on every exported symbol in their src modules and `eslint-plugin-tsdoc` checks its syntax. The behaviour specification page is generated from test names. The site is built and link checked in CI and deployed to GitHub Pages from `main`.

## Consequences

- Good: the API reference and behaviour specification cannot drift from the code.
- Good: a broken link or an undocumented public export fails CI.
- Bad: a docs toolchain with its own dependencies to keep current. Dependabot covers them.
- Bad: starlight-typedoc and typedoc track Starlight and TypeScript releases, so a TypeScript upgrade may wait on typedoc support as well (see ADR 0007).
